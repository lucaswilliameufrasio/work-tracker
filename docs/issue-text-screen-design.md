# Private expected-version text editor

Slice244 adds `/projects/{uuid}/issues/{number}/edit`, separate from board/detail. It edits only title/plain Markdown-source description (blank clears), with a version label and explicit save. No rendered Markdown, arbitrary field changes or silent auto-save. Extend the advisory project capabilities DTO with explicit can_replace_issue_text derived from the existing MutateIssues policy; creation stays independently named. Both flags remain hints, never authorization tokens. The editor loads current session, same actor, capability and issue; archived/viewer/managerless or trashed issues have no editable form. PUT revalidates independently.

Use a discriminated state machine and generation/abort guards. Draft values and base version live in one in-memory work model and in tab-scoped `sessionStorage`, never in URLs or logs. The record is bounded and schema-versioned, keyed by actor, session, project and immutable issue identity. Restore only after fresh session, capability and issue reads, followed by a second session identity check; a changed base version restores as a conflict, never as an automatic rebase. On blur/hidden/pagehide remove private DOM synchronously; transient network failures hide but preserve the draft for the same session. Logout/current-session revocation, observed expiry/401, changed identity/session, or detected loss of project/issue access clears the applicable stored draft(s) and in-memory work. Late read/write completions after suspension/disposal are ignored. Storage read/write/clear failures block editing or PUT and expose an explicit retry state.

`sessionStorage` survives reloads in the same tab but is not encrypted and is accessible to scripts from the same origin. Do not claim secrecy from same-origin script execution or guarantee physical erasure from browser backups/session restoration. Closing the browsing context may discard the only draft/uncertain-command copy. No cross-tab synchronization, background submission or offline write is provided.

One save snapshots text/base version and generates one UUID; persist the exact command and key before sending. Duplicate save is blocked. Success clears the command and draft, shows only stable receipt/link. An uncertain network/abort/invalid response locks editing/new keys and offers only explicit same-request/key resend, including after reload. Never infer a commit from comparing current text. A definite409 issue_version_conflict clears only the rejected command, retains the draft/base version and offers an explicit read of current issue. Review shows draft and current text as plain data. User must explicitly choose either keep draft against the reviewed current version or discard draft for current values; neither choice sends PUT. A later Save uses a new key/version and can conflict again. No automatic merge, overwrite, key change or retry.
