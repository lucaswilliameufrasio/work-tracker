# Private expected-version text editor

Slice244 adds `/projects/{uuid}/issues/{number}/edit`, separate from board/detail. It edits only title/plain Markdown-source description (blank clears), with a version label and explicit save. No rendered Markdown, arbitrary field changes or silent auto-save. Extend the advisory project capabilities DTO with explicit can_replace_issue_text derived from the existing MutateIssues policy; creation stays independently named. Both flags remain hints, never authorization tokens. The editor loads current session, same actor, capability and issue; archived/viewer/managerless or trashed issues have no editable form. PUT revalidates independently.

Use a discriminated state machine and generation/abort guards. Draft values and base version live in one in-memory work model, not in URLs/storage/logs. Keystrokes update that model. On blur/hidden/pagehide remove private DOM synchronously; retain the in-memory draft, then revalidate identity/access before restoring. Invalid/expired session, changed principal or lost access purges the draft/command; transient network errors hide but preserve it for the same actor. Late read/write completions after suspension/disposal are ignored. This slice does not promise draft survival after full reload; the canonical session-only persisted-draft requirement remains a separate release gate.

One save snapshots text/base version and generates one UUID. Duplicate save is blocked. Success clears the command and draft, shows only stable receipt/link. An uncertain network/abort/invalid response locks editing/new keys and offers only explicit same-request/key resend, even after focus restoration. Never infer a commit from comparing current text. A definite409 issue_version_conflict clears only the rejected command, retains the draft/base version and offers an explicit read of current issue. Review shows draft and current text as plain data. User must explicitly choose either keep draft against the reviewed current version or discard draft for current values; neither choice sends PUT. A later Save uses a new key/version and can conflict again. No automatic merge, overwrite, key change or retry.
