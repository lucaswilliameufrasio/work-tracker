# Browser session transport security — feature design

**Status:** Slice 214 implemented; transport primitives, not exposed routes.
**Source:** `docs/development-plan.md` §7.2/9: Secure/HttpOnly/SameSite=Lax cookie, CSRF on cookie mutations, Origin/Host validation, no implicit proxy trust.

`BrowserSessionSecurity` is constructed with an explicitly configured HTTPS origin and the installation master key. It never derives its origin from Host/Forwarded/X-Forwarded-* request input. Configuration rejects credentials, path prefixes, query/fragment, non-HTTPS and malformed authority. Default port 443 is canonicalized away. Request Host must match the configured authority; conflicting absolute-form URI authorities/schemes are rejected. No CORS wildcard or alternate origin is enabled.

The sole browser session cookie is `__Host-puxiri_session`: Path=/, Secure, HttpOnly, SameSite=Lax, no Domain, Max-Age bounded by the issued session expiry. Clear-cookie uses the same attributes and Max-Age=0. Exactly one canonical 256-bit session value across all Cookie headers is accepted; malformed/duplicate values and total cookie headers above 8 KiB fail closed. Authorization headers are not a fallback for browser session endpoints. The Apple POST callback remains a separate protocol flow; this cookie is not weakened to SameSite=None.

All supplied Origin values must exactly match the configured origin, with missing/multiple/null/foreign origins rejected on unsafe methods. Fetch Metadata, when present, permits only same-origin or user-initiated `none` and rejects same-site/cross-site; no claim is made that it replaces CSRF. Unsafe methods additionally require exactly one `X-CSRF-Token`.

The CSRF value is a server-derived 256-bit HMAC under the existing master-key domain-separated digest mechanism, bound to the session token digest with namespace `browser-session-csrf-v1`. It is not the session bearer and cannot authenticate on its own. A legitimate current-session adapter can return it in a no-store same-origin response; it must never be placed in URLs, cookies, logs or persistent browser storage. Deterministic per-bearer derivation supports multiple tabs without invalidating each other's tokens; rotation changes the CSRF value and session revocation is enforced independently by current session validation. It is reusable for that bearer, not a one-time action proof. Key rotation invalidates this value. Comparison is constant-time after strict encoding/size checks. This avoids adding a second CSRF table or making a GET mint persistent mutable state. It does not solve pre-login CSRF; login/setup have separate gates.

`authenticate_request` validates transport and CSRF but does not look up or authorize a session: handlers must subsequently validate the token and execute session-bound operations in their own transaction. No account or project ID comes from this validator. Secret-bearing output headers are marked sensitive. Unit tests cover hostile origins/hosts/duplicates/cookie flags and CSRF binding/rotation; actual HTTPS browser storage/SameSite behavior remains a distinct end-to-end gate.
