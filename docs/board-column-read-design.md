# Session-bound board column reads

Slice232 starts the board journey with GET/HEAD `/api/v1/projects/{project_id}/board/{status_id}`: an explicit current project member reads one visible, nonarchived status, its retained nontrashed issue count and a bounded card page. Archived projects stay readable. Hidden/backlog/canceled statuses are not implicitly columns; they require board_visible=true. Missing/foreign/inaccessible/non-column selections share generic404. No write, rank movement, filtering, SSE or complete board UI is enabled here.

Session identity, membership, status eligibility, count and cards share one SQLite read snapshot. Use the existing `(project_id,status_id,trashed_at,rank,id)` index for count and ordered seek. Read page_size1–100/default20 with one lookahead, ascending `(rank,id)`; no offset or whole-column materialization. COUNT visits matching index entries; bounded rows do not imply constant-time SQL, RPS capacity or byte/allocation caps. No new migration or dependency. All three signed-i64 rank extremes are valid. Count and rank are decimal JSON strings to preserve precision; summaries are the existing field allowlist plus read-only rank (not an accepted mutation command).

Opaque cursor is canonical Base64URL without padding of `rank/event-independent issue UUID`, with signed canonical decimal rank (no plus, leading zero, negative zero or overflow). Validate byte length/re-encoding, UTF-8, rank and UUID. The cursor is only an exclusive boundary, not authority and not a requirement for a surviving row. Revalidation of project/status occurs on every page. Future concurrent moves can change traversal between requests: no cross-request frozen snapshot or exactly-once traversal guarantee. Same-rank cards use UUID as tie-breaker.

Tests use the actual router/migrated SQLite for ordering/ties/extremes, count/trash, cursor boundaries, page limits, foreign/ineligible status, archive policy, current session/membership/ban/expiry and corrupt storage. EXPLAIN verifies index seeks without temporary sorting. Extend generated partial OpenAPI with both operations and real schema checks. A later vertical UI slice will compose bounded columns; creation/edit/move requires optimistic version, idempotency, history and outbox before enabling writes.
