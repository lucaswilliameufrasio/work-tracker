# Validated project catalog client

Slice229 connects the existing status/issue-type reads to TypeScript using the issue read transport (same-origin cookies, eight-second deadline,512KiB streamed byte cap,64KiB errors, no retry/redirect/automatic traversal). There is no catalog editor, board screen, login or setup change. A caller explicitly selects project, page size, UUID boundary and archive inclusion; runtime validation rejects malformed selectors before fetch.

Parse unknown DTOs with strict allowlists, matching project ID, canonical IDs/UTC, known categories, boolean visibility and nonnegative i64 decimal positions without Number conversion. Optional keys and archived_at must be omitted rather than null. Type icon/color tokens remain opaque strings matching persisted grammar; no visuals are invented. Names have no arbitrary new read-side character cap because storage currently has none; the transport byte cap still rejects oversized responses safely. Reject empty/short continuation pages, nonascending IDs or continuation not equal to the last item. Default archive exclusion also rejects a response that unexpectedly contains archived rows. Include-archived never grants access and does not imply archived records are editable.

Page order is UUID traversal order, not display order. Consumers must distinguish partial catalog data from a complete catalog and explicitly request additional pages when resolving issue references. No silent fallback to guessed localized names, invented statuses or unbounded eager traversal is introduced. Tests run the actual TypeScript module against migrated SQLite/router in the existing Node fixture, plus parser/protocol tests for malformed/scoped/ordered data and safe transport errors. Node cookie injection is fixture-only, not browser TLS/SameSite evidence.
