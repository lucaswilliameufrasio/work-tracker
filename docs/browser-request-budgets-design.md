# Browser request admission and envelope budgets

**Status:** Implementation slice221; development defaults, not measured deployment capacity.

The existing browser routes perform transport checks, a throttled session touch, then session-bound SQLite work. Four SQLite connections bound running SQL but do not bound tasks waiting to enter the pool. Protect only the opt-in browser router with a shared, non-waiting admission gate: eight in-flight handler requests per router instance, including empty-body verification, held until the handler constructs its response (not until the socket finishes sending it). A full gate rejects immediately with generic503 `service_busy`, retryable=true and `Retry-After: 1` as minimum client backoff, not an availability promise. All clones of one router share this gate. Separate router instances/processes do not; this is neither per-user fairness nor requests-per-second limiting. Health/frontend/default closed routes do not acquire these permits. Connections, slow readers and response-send buffering are not bounded by this gate.

Current endpoints take no request body. Before auth, activity touch or mutation, bound URI path+query to2KiB, headers to64 entries/16KiB aggregate name+value bytes, and payload to zero bytes. Reject URI excess with414 `uri_too_long`, header excess with431 `headers_too_large`, and any nonempty body with413 `payload_too_large`. Explicit Content-Length must be one valid unsigned decimal value; nonzero is413, invalid/duplicate Content-Length or Content-Length plus Transfer-Encoding is400 `malformed_request`. HTTP server parsing may reject malformed framing even earlier, outside this JSON contract.

Unknown-length/chunked bodies must finish empty within one second, otherwise408 `request_timeout` (retryable=true), **before any handler starts**. This timeout applies only to body verification, never to a transaction/handler future: do not cancel a committed mutation and claim it did not happen. No entire-handler/SQL timeout, connection/slow-header timeout or response-stream limit is implemented. A bounded zero-byte collector rejects the first payload data; it does not buffer an entire upload. Cancellation/error/success drops the admission permit. No queued admission tasks or durable acceptance are introduced.

The already locked/test-used `http-body-util` crate is declared as a direct production dependency to distinguish its typed `LengthLimitError` (413) from other body read failures (generic400), rather than matching error strings or treating a transport failure as an oversized upload. No new resolved package/version is selected. HEAD budget rejections suppress bodies too.

Every rejection uses the project JSON error envelope/no-store and outer security headers, without reflecting header/body/URI/token contents or clearing cookies. Tests must prove saturation does not queue, router clones share permits, permits return on cancellation and failures, exact byte/count boundaries, empty/hostile bodies and no DB/audit effect for rejected browser mutations. A local real-HTTP incomplete chunked-body test covers timeout; it is not a slowloris/load-capacity or proxy certification. Update the generated partial OpenAPI error responses. Per-account/IP throttles, configurable operating limits, low-cardinality operational metrics, handler/SQL/connection budgets and production sizing remain separate gates.
