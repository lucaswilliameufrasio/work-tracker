# Session-screen lifecycle revalidation

Slice224 follows the controlled slice223 journey. A persisted-page event regression showed two private rows still present after `pagehide`; the component only cleaned up on unmount, which is not the same as a browser-history freeze. The initial headless-tab test could not establish real visibility changes (`visibilityState` remained visible), so it was replaced with an explicit standard lifecycle-event seam. Do not mislabel synthetic persisted events as proof that a real BFCache entry was created/restored.

On window blur, hidden visibility or pagehide, abort the current operation, invalidate its generation and synchronously remove private list/confirmation DOM via Svelte flushSync. A pending termination becomes an unconfirmed outcome, never a failed/successful claim. On visible focus, visible restoration or persisted pageshow, perform at most one fresh **read**, not a resumed DELETE. New operation generations suppress old reads/commands that complete despite cancellation. Terminal signed-out states need no private-data refresh. Confirmation is discarded on leaving the page.

Use one additional `suspended` union state; request controllers/generation counters are technical cancellation state, not independent UI mode booleans. Keep the screen's lifetime abort separate from replaceable operation cancellation. Lifecycle restoration after an unconfirmed termination carries an uncertainty notice with the fresh page so it cannot be mistaken for a confirmed mutation. This does not make browser/client cancellation a rollback guarantee. Revalidation is point-in-time, not a live subscription to all later revocations.

Serve the public HTML shell at the private-task path with `Cache-Control: no-store` as defense in depth; it contains no server-rendered private data. This header alone does not guarantee that current/future browsers disable BFCache. Browser tests cover synchronous DOM clearing at explicit lifecycle events, read-only restoration and actual server revocation in a second tab; workflow tests cover stale completion suppression and canceled confirmations/submissions. Physical history/BFCache eligibility, renderer-memory/forensic erasure, additional engines and hidden-tab behavior remain distinct acceptance evidence.
