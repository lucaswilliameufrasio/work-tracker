# Session-bound project issue listing

Slice225 connects the existing authorized issue-list query to opt-in `GET/HEAD /api/v1/projects/{project_id}/issues`. The actor is an active session holder with explicit current project membership (manager/member/viewer, including eligible guests). Organization owner/admin or installation-admin authority alone never grants issue content. Archived projects remain readable; trashed issues stay excluded. Missing and inaccessible projects share generic404, while an invalid session is401.

Keep session authentication, project authorization and issue selection inside one SQLite read transaction. Do not call an ID-based query after an independent authentication check. Extract a caller-owned transaction helper from the existing query, preserving the internal API for its existing callers. No principal IDs, roles or MFA assurance come from the request. HTTP preflight may still perform the existing separate throttled activity touch; it does not authorize the content read.

Accept only `cursor` (canonical positive decimal issue number) and `page_size` (1–100, default50), with one lookahead row and immutable issue-number ascending order. Cursor boundaries need not exist and do not grant access. A traversal across requests is not a frozen snapshot. Return the existing page envelope, summaries without description/history/rank, optional assignee/due-date omitted, and UTC timestamps. Issue numbers and versions are **decimal JSON strings**, preserving the existing full positive SQLite i64 domain without JavaScript precision loss; `issue_key` remains human-readable. Cursor parsing rejects signs, zero, leading zeroes, nondecimal text and i64 overflow. IDs are canonical UUIDs.

Use the existing shared browser admission/envelope/Host/Origin/Fetch/cookie protections and central no-store error contract. This read-only route accepts no body or mutation methods. Update generated OpenAPI and test every documented operation with real router/SQLite. Tests must cover membership/role changes, account/session invalidation, archived reads, trash exclusion, private404 equivalence, pagination/concurrent creation, lossless large numbers, malformed paths/queries, corrupt storage and failure without private reflection.

No issue detail/history endpoint, board ranking, FTS/filter search, mutation/idempotency/outbox, MCP credential path, login/setup or issue UI is enabled by this slice. These remain separate journeys; the list is not a complete Kanban release.
