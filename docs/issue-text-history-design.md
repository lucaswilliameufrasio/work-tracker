# Content-free repeated text-change journals

Slice240 prepares the read/schema side of versioned text editing without enabling an edit command or route. Migration0032 preserves all issue_events/outbox IDs/actors/timestamps/content-free metadata, keeps exactly one issue.created journal entry per issue, and permits repeated issue.title_updated, issue.description_updated or issue.text_updated (both fields) journal kinds. Event kind identifies which free-text fields changed; no previous/new text, diff or payload blob is retained. Existing created history wire shape is unchanged. Journal timestamps/UUID keysets remain the read ordering, not a version cursor.

Outbox envelopes remain version1 payloads, immutable on UPDATE, with IDs/actor/project/issue version/time only. Created envelopes require issue_version1; the three text-update kinds require issue_version>=2. Unique(issue_id,issue_version,event_kind), FKs and time index are retained. This does not create a worker, delivery, retrospective events or a user-facing edit mutation. No text is copied into history/outbox by migration. Tables are rebuilt transactionally using the repository migration runner; old indexes/immutable envelope trigger are explicitly recreated.

Rust/HTTP/OpenAPI/TypeScript history readers accept only these exact typed kinds, retaining strict shapes and safe text labels in the UI. No unknown event kind becomes arbitrary rendered HTML. Creation paths and existing receipts are unchanged. Before enabling editing, implement a session-bound expected-version command, idempotent stable mutation receipts, atomic issue/version/history/outbox, no-op semantics, current mutation permission and trash/archive rules. Text-change history does not establish optimistic concurrency by itself. Structured field before/after history remains future work.

Full gate required before delivery. Production release/backup migration gates remain open.
