# Session-bound expected-version text replacement

Slice241 implements an internal command only: replace the full title/optional description, not an arbitrary field patch. Omitted description means clear; future transport must document that full-replacement contract. Validate title/description like creation, canonical UUID idempotency key and positive expected version. In BEGINIMMEDIATE authenticate bearer/current account, authorize current MutateIssues, reject archived/managerless/private projects and trashed/missing issues, then consult receipt before comparing the current version. Other issue fields remain unchanged.

Operation issue.replace_text has its own actor/key namespace across issues/projects and sessions. Persist SHA256 domain-separated key digest and a master-key HMAC over streaming JSON-tuple SHA256(project,issue,expected_version,raw title,optional description), never free text/key. Same key/different payload conflicts; different master selector fails closed. Exact replay checks current authority/resource eligibility and returns stable issue/project/number/key/result_version/changed references even after later edits, never previous/current text. It does not reapply or compare expected_version against the newer state. Receipt result must not exceed current issue version. Missing/purged or trashed resource never gets recreated/edited by replay.

For a new key, wrong current version is conflict without reserving key. Compare trimmed stored title and optional description; exact effective no-op preserves version/timestamp and adds no journal/outbox, but persists an immutable changed=false receipt so a retry cannot become a later mutation. A real change increments version with checked i64 arithmetic, refuses clock regression against stored updated_at, updates only title/description/version/updated_at, inserts one typed content-free journal and one versioned outbox envelope, and persists changed=true receipt in the same commit. Title-only/description-only/both select the three240 kinds. Failure at any write rolls back everything. No external publication or timeout wraps this transaction.

Migration0033 creates immutable content-free text receipts with no TTL/delete/reuse, retaining target IDs independently of future purge, like creation receipts. Existing issue creation receipts/fingerprint namespaces remain unchanged. Storage quotas/retention/key rotation/recovery and production purge policy still need review. No HTTP/MCP route, editor, arbitrary type/status/assignee/priority/due-date changes, move, dispatcher or worker is enabled.
