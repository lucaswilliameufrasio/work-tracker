# Validated browser issue read client

Slice227 implements only a TypeScript client for the three existing issue read routes. No UI, mutation, login, setup, provider or automatic traversal is introduced. Fixed relative API paths, canonical selectors before fetch, same-origin cookies, no bearer/cookie storage, no redirects/retries, caller cancellation and an eight-second whole-read deadline match the session client's boundary. It stays separate from the session mutation client to avoid changing its established CSRF and uncertain-result semantics.

Responses enter as unknown. Strict field allowlists validate IDs, matching project/issue selectors, decimal-string positive i64s without Number coercion, priorities, dates, canonical UTC timestamps and optional-field omission (not null). Text remains unrendered data, with Unicode scalar title limits and UTF-8 description limits. Page validators require strict keyset order, unique IDs and exact last-item continuation for full pages, rejecting empty/nonprogressing continuations. History cursors mirror the server's canonical Base64URL timestamp/UUID encoding; actors/events carry no text body. This does not prove future multi-event server pagination: current SQLite only permits one creation event per issue.

Read at most512KiB of response bytes, canceling streams at overflow; error bodies retain64KiB. A64KiB description consisting of JSON-escaped controls can require393216 bytes before envelope overhead; the session client's64KiB cap would reject valid detail and large list responses. The larger bound supports the current100-row/240-scalar title contract, not arbitrary future payload expansion. Errors expose only status/code/request_id/retryable, never raw server messages/field errors/network internals. Test malformed JSON/UTF-8, content type, error envelopes, streaming limits, timeout and cancellation at the fetch/body boundaries.

Verification uses unit protocol seams plus the real TypeScript client against a loopback HTTP router and migrated file-backed SQLite, including large escaped details, pagination, archived/trash reads and denied/expired sessions. Node's cookie adapter is test-only and does not certify Secure/SameSite/TLS, browser engines or production proxy behavior. Those browser matrices remain open.

The no-emit TypeScript configuration permits explicit `.ts` imports so Node24's built-in strip-only loader can execute the actual client and its transport without a generated duplicate. Avoid parameter properties and other runtime-transform syntax unsupported by that loader. Vite still owns browser bundling; no runtime loader dependency is added.
