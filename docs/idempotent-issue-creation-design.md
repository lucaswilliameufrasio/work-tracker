# Session-bound idempotent issue creation and durable events

Slice235 supplies the write foundation before browser POST/UI: authenticated project manager/member creates an issue, loses the response, and explicitly repeats the same operation/key without creating a second issue. Use BEGIN IMMEDIATE for session identity, current MutateIssues authorization, receipt lookup, number/rank allocation, issue/history/outbox/receipt and commit. No external call or event publication occurs inside or before that commit. Existing trusted-ID creation delegates to the same transaction-owned helper and also persists the creation outbox event. It remains internal and non-idempotent unless invoked by the session writer.

Accept a canonical UUID idempotency key, scoped to actor and the fixed issue.create operation across projects (not session ID). Store a domain-separated SHA256 key digest, never the raw key. Compare a master-key HMAC of the SHA256 digest of a fixed versioned JSON tuple(project_id, raw title, optional description, optional assignee). Stream serialization into the digest rather than allocating another copy of free text; only the keyed fingerprint is persisted. JSON object ordering is irrelevant, string/absence differences remain different requests, even if title trim would produce the same stored title. Validate title/description bounds before mutation. Store the master key's nonsecret selector with the fingerprint. If a receipt's key selector differs, fail closed instead of treating it as absent; rotation cannot silently duplicate an operation. Request fingerprints use constant-time comparison and are not plain low-entropy text hashes. No new crypto primitive/library is introduced.

Same actor/key plus a different valid payload is a conflict. Same request returns a stable creation receipt containing issue/project/number/key/created_version only, not historical or current free text. Replay first revalidates active session and current mutation permission, including project archive/manager availability; it never restores revoked authority. It checks that the original issue still exists with the immutable identity/authorship. A missing/purged issue returns unavailable and never recreates it. Other principals have independent namespaces. Assignee/default-schema creation checks run for a new issue, not as if replay reassigns anything.

Conservative initial retention: no TTL, deletion, sweep or reuse of receipt slots. This avoids silently reexecuting an ambiguous request after a cleanup window; minimal content-free tombstones may outlive a later purge (receipt issue_id is intentionally not an issue FK). This is internal development behavior, not a public infinite-retention SLA. Before enabling production retention/purge/anonymization flows, review bounded storage/quotas and key rotation/recovery; do not add a short expiry by assumption. Stable references/authorship remain compatible with existing account anonymization, which already preserves user IDs and work.

The typed outbox envelope is version1 issue.created: IDs, actor, issue version and UTC time, with uniqueness per issue/version/kind and no title/description/payload blob. Persist for all real creation paths in the same transaction. There is no dispatcher, job lease, retries, notification, rule execution or SaaS traffic in this slice; retained events do not prove background delivery or exactly-once effects. Future workers must claim durably, revalidate relevance/access and use bounded idempotent delivery. Outbox FKs preserve referenced work until future delivery/purge coordination is implemented.

Migration0031 does not fabricate retrospective outbox events for existing issues. Only creation commits after applying it produce envelopes; worker rollout/backfill policy remains explicit future work.

Verification uses file-backed migrated SQLite: exact replay/conflict/principal/project scoping, cross-session reuse, concurrent duplicates, restart, expiry/ban/membership/archive/default/assignee rules, low-entropy text/key absence from stored receipts/outbox, and trigger-injected rollback at history/outbox/receipt writes including counter restoration. No HTTP issuance, login/setup or mutation UI is enabled by this slice. Generic idempotency for other commands, editing/moves, outbox workers, rate/retention budgets and release gates stay open.
