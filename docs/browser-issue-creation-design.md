# Opt-in idempotent browser issue creation

Slice236 adds POST `/api/v1/projects/{project_id}/issues` only to the explicitly configured browser router. It accepts title plus omitted optional description/assignee_user_id; unknown/duplicate fields, explicit null, invalid JSON/UTF-8 and query selectors are rejected. Assignee/project IDs are canonical UUIDs. Type/status/rank/priority/due date/actor cannot be supplied. Existing domain limits/defaults/assignment and current membership/archive/manager rules apply.

Require same-origin transport, exact current cookie's CSRF and a single canonical UUID Idempotency-Key. Revalidate current persisted session and mutation authorization inside SessionIssueWriter's BEGIN IMMEDIATE; no role/assurance comes from client data. Generic404 covers unavailable private/read-only project. Invalid fields422, valid changed request/key409 idempotency_conflict, unavailable default schema/capacity409, storage503 and corrupt state500 are safe envelopes. A mismatched fingerprint key is503 idempotency_unavailable/retryable=false, not permission to choose a new key and recreate an uncertain operation.

The common eight-permit/no-queue URI/header/framing admission remains. Only POST on the actual matched issue collection route permits a body. Before collecting it, check stateless Host/Origin/Fetch/cookie/CSRF, content type application/json (optional UTF-8 charset only) and absence of Content-Encoding. Collect at most512KiB with the existing one-second body deadline; CL+TE, duplicate/invalid CL/TE and completed length mismatches are malformed. Reject oversize413, unsupported encoding/media415, incomplete/slow408. No DB transaction or activity touch starts for these pre-handler rejections. Other routes keep zero-body policy. The cap covers JSON escaping of a64KiB description; approximately4MiB of body buffers at eight admitted requests is not a bound on the whole process or connections, nor an RPS/quota guarantee.

Return201 for first commit and exact replay, with no-store, relative Location and a content-free receipt `{id,project_id,issue_number,issue_key,created_version}` (i64 values as strings). Idempotency-Replayed is true/false, never the raw key. No cookie change, historical text or event publication. Commit precedes successful response. An interrupted response is uncertain; callers must preserve the same request/key, never auto-retry or silently switch to a new key. The receipt retention/key-selection limitations of slice235 still apply; this is opt-in development API, not production auth/quota/retention approval.

Tests use actual router/SQLite for create/replay/conflict/concurrency, current authority, payload/framing/CSRF rejection before side effects, serialization, rollback and safe errors. Update partial OpenAPI and every-operation contract tests for the first JSON-body POST (all other operations remain bodyless). UI/client creation, live providers, background delivery and login/setup remain separate.
