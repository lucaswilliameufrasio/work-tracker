# Session-bound browser project API — feature design

**Status:** Slice 215 implemented; explicit HTTPS-origin opt-in, read-only endpoints.
**Source:** `docs/development-plan.md` §6–7/9; existing browser transport and session-principal design notes.

`serve --browser-origin https://tracker.example.test` explicitly enables `/api/v1/auth/session`, `/api/v1/projects`, and `/api/v1/admin/projects`. The option is absent by default; it is transitional operator configuration until protected installation settings exist. Configuration is parsed before opening the data directory. The configured origin is not inferred from bind address, Host, Forwarded or X-Forwarded headers. This listener does not terminate TLS; an operator must provide HTTPS at the approved origin and prevent untrusted direct/proxy access. This is not a deployment operation.

Each endpoint is GET/HEAD only. Browser cookie/Host/Origin/Fetch Metadata validation precedes token lookup; current `SessionStore::validate` handles throttled activity and session expiry. Project reads then revalidate the same bearer, current authority and data in one SQLite read snapshot via `SessionProjectReader`. No request accepts actor/user identity. Accessible projects still require explicit membership. The admin catalog requires current owner/admin authority and returns metadata/counts only. The current-session response contains only user/session IDs and its separate CSRF value, never the bearer, email, roles or secret key; it revalidates identity in its own transaction.

List query fields are `cursor` (stable project key), `page_size` (1–100/default50), and `include_archived` (defaultfalse); duplicates/unknown fields and malformed representations are rejected. The response is `{ data, has_more, next_cursor? }` with optional archive timestamps omitted rather than null. Timestamps are UTC ISO-8601. Operational counts have the slice212 definition, including retained inactive memberships and trashed issues.

All success/error responses are no-store. Errors use the already specified project envelope (`code`, `message`, `request_id`, `field_errors`, `retryable`), with fresh server request IDs and no raw SQL, token, header, query or internal error reflection. Invalid cookie/session gives401, forbidden origin/operational capability403, unknown route404, unsupported method405, malformed query400, domain pagination validation422, and storage failure503. There is no CORS allowlist expansion or wildcard.

No login/signup, session issuance, unsafe mutation, setup bypass, privileged assurance or frontend is added. Existing internal data is required for a usable authenticated request; tests seed only temporary synthetic databases and sessions. Local router/HTTP tests are evidence for request wiring and persistence, not browser HTTPS/SameSite storage or a complete onboarding journey. Those, OpenAPI, request budgets/rate limits and UI remain follow-up gates.
